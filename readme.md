# Shop Checker Bot

Моніторинг каталогу монет НБУ через Playwright зі сповіщеннями в Telegram.
Порівнює товари зі знімком `data/products.json` за ID, назвою та URL.
Після успішного надсилання змін у всі налаштовані чати знімок оновлюється.
Ціна й наявність поки не відстежуються.

## Налаштування та запуск

Потрібні Node.js 24+ і pnpm 11.24.0. TypeScript запускається без збірки.

```sh
pnpm install
pnpm exec playwright install chromium
```

Створіть `.env` за прикладом `.env.example`:

```env
BOT_TOKEN=your_bot_token
CHAT_ID=your_chat_id
CHAT_ID_2=
```

`CHAT_ID_2` — необов’язковий ID другого чату. Якщо його заповнити, бот
надсилатиме однакові повідомлення в обидва чати. Однакові ID не дублюються.
Кожен отримувач має спочатку відкрити бота в Telegram і натиснути Start.
Команди запуску завантажують `.env`; цей файл виключено з Git.
Робочий знімок зберігається в `data/products.json`. Для нового встановлення
створіть папку `data` та скопіюйте туди кореневий `products.json` один раз.
Не замінюйте вже наявний робочий знімок під час оновлення проєкту.
Папку `data` виключено з Git та образу Docker; кореневий файл є лише початковою копією.

```sh
pnpm start       # запуск моніторингу
pnpm dev         # перезапуск після змін коду
pnpm typecheck   # перевірка типів
```

## Запуск у Docker

Потрібен запущений Docker Desktop (або Docker Engine із Compose на Linux).
Підготуйте `.env` і `data/products.json`, як описано вище.
Локально встановлювати Node.js, pnpm чи Chromium для цього запуску не потрібно.

```sh
docker compose up --build -d
docker compose logs -f
```

Зупинка та видалення контейнера:

```sh
docker compose down
```

Chromium працює з `headless: false` на віртуальному екрані Xvfb всередині
контейнера, тому вікна не відкриваються на робочому столі. Telegram-параметри
передаються через оточення; `.env` не потрапляє в образ. Папка `data`
монтується для читання та запису; знімок зберігається після заміни контейнера.
На Linux папка має бути доступна для запису користувачу контейнера (UID 1000).
Після зміни коду повторіть команду з `--build`. Запускайте лише один екземпляр
бота для одного знімка. Під час переходу зі старої версії спершу зупиніть її.
Docker і комп’ютер мають залишатися запущеними. Помилка, зокрема 403,
зупиняє процес; автоматичного перезапуску контейнера не налаштовано.

## Як працює моніторинг

- `main.ts` запускає один видимий браузер і послідовно виконує перевірки.
- Кожна перевірка відкриває нову сторінку, чекає до 5 секунд на перше
  посилання товару та ще 1 секунду перед читанням списку. Ця затримка
  не гарантує завантаження всіх динамічних елементів.
- Після перевірки програма надсилає повідомлення, чекає заданий інтервал,
  закриває сторінку й починає наступну перевірку.
- Без змін повідомлення містить перші 30 символів назви кожного товару.
- За наявності змін — списки доданих, змінених і відсутніх товарів
  із повними назвами, ID та URL.
- Повідомлення довші за 4 000 символів обрізаються з позначкою `[Message truncated]`.
- Без змін повідомлення надсилається, якщо після останнього успішного
  сповіщення минуло 3 години. Після запуску перше повідомлення надсилається одразу;
  таймер зберігається лише в пам’яті. Сповіщення про зміни також скидає таймер.
- За наявності змін повідомлення надсилається одразу, після чого поточні товари
  атомарно записуються в `data/products.json` через тимчасовий файл і перейменування.
  Наступна перевірка порівнює сайт уже з оновленим знімком.
- Якщо надсилання не вдалося, знімок не оновлюється. Поточна обробка помилок
  завершує процес; після перезапуску зміни будуть надіслані повторно.
- Якщо один чат отримав повідомлення, а інший — ні, перший може отримати дублікат
  після перезапуску. Також повтор можливий, якщо запис знімка після надсилання не вдався.

Налаштування в `src/variables.ts`:

| Константа | Поточне значення |
| --- | --- |
| `CHECK_INTERVAL_MS` | 20 секунд після завершення перевірки |
| `PRODUCT_LOAD_DELAY_MS` | 1 секунда перед читанням товарів |
| `PRODUCT_WAIT_TIMEOUT_MS` | 5 секунд очікування першого посилання |
| `TELEGRAM_MAX_MESSAGE_LENGTH` | 4 000 символів разом із позначкою обрізання |
| `NO_CHANGE_MESSAGE_INTERVAL_MS` | 3 години між повідомленнями без змін |

Зупинка: Ctrl+C. Комп’ютер має бути увімкнений, не спати й мати інтернет.
Наразі помилка перевірки або Telegram (зокрема HTTP 403) завершує
моніторинг і закриває браузер. Автоматичного повтору після помилки немає.
